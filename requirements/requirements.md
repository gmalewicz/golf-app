| CR-05 | Update the player's WHS handicap index (`whs` in `Player`) from the Polish Golf Association (PZG) service by a scheduled job. Add an optional `pzgId` (Long) field to `Player` (database column, nullable); players without it are skipped. The functionality shall be switched on and off by the configuration parameter `pzg.enabled` (boolean, in `application.yml`, bound through a `@ConfigurationProperties("pzg")` class like the other `*Config` classes, default `false`, overridable by the environment variable `PZG_ENABLED`); no code change or redeployment of the front end is needed to change it. When it is `false` the PZG service is never called, no PZG login is made and `whs` is not modified; when it is `true` the job updates all players that have `pzgId` set. The job runs every day at 3:00 a.m. (Europe/Warsaw time zone); the sign-on does not call PZG and is not affected in any way. The PZG service base URL, user name and password shall be configuration properties of the same `pzg` group (`pzg.url`, `pzg.username`, `pzg.password`). The credentials are stored in the environment variables `PZG_USER` (user name) and `PZG` (password) and shall be mapped to `pzg.username` and `pzg.password` in `application.yml`. During a run the backend shall log in to the PZG service (`POST /api/_account1/auth/login`, body `{"email","password"}`, the response contains `token`) with a technical account whose credentials are taken from configuration or environment variables (never stored in the repository), then for each player call `GET /api/_account1/member/get_profile?id={pzgId}` (Bearer token) and store `member.hcp` in `Player.whs`. The token shall be cached and a new login performed when it expires (HTTP 401). The PZG call has a short timeout (`pzg.timeoutMs`, default 3000 ms). An error for one player (member not found, invalid or out of range (-5 to 54) value) is logged and the existing `whs` value of that player is kept, and the job continues with the next player; the job is aborted (and logged) after 5 consecutive failures, e.g. when the service is unavailable. Only the `hcp` value is read from the response; the photo and the other profile data shall be ignored and not stored. |
| CR-06 | In the Player management page (admin, `players.component`) add a new column "PZG ID" between "ID" and "Rounds" displaying `pzgId` of the player or `n/a` when it is not set (null). Clicking a cell in that column opens a dialog (Angular Material, same style as the existing player update dialog) with a single numeric input pre-filled with the current `pzgId` (empty when not set) and Save and Cancel buttons. Save is enabled only for a positive integer or an empty value; an empty value clears `pzgId` (the player is then skipped by the PZG handicap job, see CR-05). Cancel closes the dialog without any change. On Save the front end calls the new endpoint PATCH /rest/PlayerPzgId with body `{"id": <playerId>, "pzgId": <Long or null>}`, available to the ADMIN role only. The backend updates only `Player.pzgId` (no other player field is modified, and the existing PATCH /rest/UpdatePlayerOnBehalf shall not change or reset `pzgId`), returns 404 when the player does not exist and 400 for a non-positive `pzgId`. After a successful response the table cell is updated without reloading the list and the success alert "The player <nick> PZG ID has been successfully updated" is shown; on error the cell is left unchanged. The endpoint `GET /rest/PlayerRoundCnt` (and `PlayerRndCnt` model) shall also return `pzgId` (Long, nullable). |
